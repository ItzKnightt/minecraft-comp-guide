# Modpacks

A modpack is a curated bundle of mods with consistent versions — the
fastest way to a good setup, and the least likely to break.

## Types of packs

| Type | What it is | When to use |
|------|------------|-------------|
| Performance | Sodium-family stack + FPS fixes | Baseline for everything |
| PvP/QoL | Performance + HUD, hit feedback, practice tools | Ranked, duels, practice |
| Feature packs | Worldgen, new biomes, structures | SMPs, exploring |
| Kitchen-sink | Everything | Messing around — never for competitive |

## Recommended starting points

- **Simply Optimized / similar performance packs** — nothing but the FPS
  stack. Perfect base to add PvP mods on top of.
- **Fabulously Optimized** — performance plus QoL that stays
  server-compatible.
- **Your own pack** — see below; it's easier than it sounds with Prism.

## Building your own (the lazy way)

1. Start a fresh instance in Prism.
2. Install the performance stack (see [Good Mods to Add](good-mods.html)).
3. Add PvP mods one at a time, testing on a server between each.
4. Export the instance (right-click → Export) so a broken update never
   costs you the whole setup.

## Version discipline

- Lock one Minecraft version per instance (e.g. 1.20.1 vs 1.21.11 have
  completely different mod ecosystems).
- When a server is on a specific version, make a matching instance —
  ViaVersion-style compat layers work for vanilla but can behave oddly with
  PvP mechanics and mods.
- Update mods *inside* a pack one at a time, not as a batch.
