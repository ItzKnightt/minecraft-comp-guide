# Speedrunning

Speedrunning settings optimize one thing: consistent chunk generation and
predictable rendering. Every millisecond you spend on a stutter is a reset
waiting to happen.

## Video

| Setting | Value | Why |
|---------|-------|-----|
| Render distance | 8–10 (or run rules) | Faster chunk meshing, fewer hitches on load |
| Graphics | Fast | Priority is CPU headroom |
| Max FPS | Uncapped during travel | Smoothness during long glides |
| Clouds | Off | Visual noise over open terrain |
| Vignette | Off | Cleaner screen |
| GUI Scale | 2 | F3 readability at speed |
| Resolution | Native | Sharpness for distance reads |

## Comfort & info

- **F3 is life.** Learn to read biome, coordinates, and chunk-border
  info without consciously parsing it.
- Reduced debug info per run rules — practice with the same rules you run.
- Keep a fixed FOV; zoom bursts during blazes/trades should be muscle
  memory, not a surprise.

## Practice-specific

- Separate practice instance: same version as the runs, no extra mods.
- A seed or world backup for structured practice (strongholds, bridges,
  bastion routes) so resets don't eat session time.
- Performance mods are allowed in most leaderboards only for render-side
  (Sodium-class); check the specific ruleset — some ban certain logic mods.
- Record attempts locally so you can review deaths; the "one more try"
  loop without review teaches nothing.

## The reset discipline

- Set a hard session structure: X minutes of resets, then Y minutes of
  targeted practice on whatever killed the last N runs.
- Track splits loosely — the goal is noticing *which* segment is
  inconsistent, not leaderboard obsession.
